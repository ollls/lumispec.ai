## 🐛 Bing returned first-word results

Every Bing search on 2026-10-31 came back with the same generic pages whatever the question:
"What is AI" (IBM, AWS, Google Cloud, SNHU) for "AI stocks sell off news…", driver downloads for
"Intel quarterly earnings stock drop…", quote homepages for "stock market today…". Bing had
received the full query — the page title and the search box showed it — but served a stripped
page with entity results for the leading term. The model's answer in that conversation survived
only because it went on to fetch articles directly; sixteen searches were useless.

The engine URL carried `setlang=en&count=10`. Measured through the extension with one query:

| Bing URL | Text on page | Organic results |
|---|---|---|
| `q` + `setlang` + `count=10` (v1.5.0) | 1,376 chars | first-word entity pages |
| `q` + `count=10` | 1,511 chars | correct, but a stripped page |
| `q` + `setlang` | 5,649 chars | 10 correct results |
| `q` alone | 5,667 chars | 10 correct results |

DuckDuckGo answered the same query correctly through the same extension, so the fetch path was
not at fault. `count=10` is gone; the Bing URL is `q` + `setlang=en`. The engine entry carries the
measurements as a comment so the parameter does not come back.

## ✅ Validation

Live, after the fix: "Intel quarterly earnings stock drop October 30 2026" → Intel Q3 coverage
(INTC −28.6%, CNBC, intc.com); "AI stocks sell off news October 31 2026" → the sell-off coverage,
twice in a row. `npm test`: 50/50 (no code path under test changed).

No `.env` change, no extension change, no reload.
