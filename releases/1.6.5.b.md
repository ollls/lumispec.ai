# LLM Workbench v1.6.5.b

## Overview

Corrections to the experimental **Amazon Cart** plugin of v1.6.5.a, and one change to every chat
answer: links open in a new tab.

No extension reload is needed (still 0.9.0).

Three commits on `dev` since v1.6.5.a (2026-11-26), 9 files, +151 / −15.

---

## 🔗 Product links

**What happened.** On 2026-11-27 a search listed products with their Amazon item number (ASIN)
and nothing to click. The address of each product page was already in the search result; the
tables printed only the number, and the prompt asked the model for the number and the picture.

- **Titles are links.** In the plugin's search and cart tables every title links to the product
  page on Amazon. The item number stays in its column, because "add the second one" uses it.
- **The model is told to link titles** in the tables it writes itself.
- **Links in an answer open in a new tab.** Before, clicking a link to another site loaded it in
  place of the app, which stopped every running turn. This applies to every link to another
  site, not only Amazon's.

## 🖼 Pictures in tables stay small

A picture in a table cell of an answer is now at most 140 px wide and tall. It had no size of its
own: the 500 px product picture took whatever width the other columns left, so the same picture
was small beside long titles and large beside short ones.

## ⏸ A refusal stops the searches already waiting

Searches the model asks for in one step run one after the other. On 2026-11-26 the first of three
drew Amazon's refusal page, and the other two, accepted before it, still loaded Amazon 6 and 15
seconds into the 30-minute pause. The pause is now checked again right before every page load.

## Known limits

- **The model can still leave pictures and links out.** Both are instructions in the prompt, not
  something the app enforces. On 2026-11-27, after these changes, "provide amazon links" was
  answered with a table that had a link column and no pictures, although every search had
  returned a picture for every product. The plugin's own tables, under "Used amazon_cart" in the
  answer, always have both.
- **With the plugin off, none of its protections apply.** It is off after every restart of the
  app. On 2026-11-27, in that state, the model loaded seven Amazon pages through `web_fetch` and
  about ten more from `run_python` with an invented browser name: the kind of traffic that drew
  Amazon's notice on 2026-11-25. No notice came this time. Turn Amazon Cart on before asking
  about Amazon.
- Everything listed as unverified in [`1.6.5.a.md`](1.6.5.a.md) still is, including adding to
  the cart end to end.

## ✅ Validation

`npm test`: 254/254 (one more than v1.6.5.a: the refusal test).

`npm run check:engines` on 2026-11-27: DuckDuckGo, Brave, Bing and Google all read correctly.

Live on 2026-11-27, with the link change running: two searches came back with 16 and 18 products,
each with a picture and a linked title in the answer. **Not checked in a browser:** the 140 px
picture bound and the new-tab click; both were written after that session.

The Amazon Cart section of the system prompt gains one line, so the first turn with the plugin on
re-reads the prompt from there. With the plugin off the prompt is unchanged. No `.env` change.
**Upgrade:** `git pull` → `npm run css:build` → restart → hard-reload the page → turn Amazon Cart
on again.
