# LLM Workbench v1.4.1

## Overview

A small, single-feature release on top of v1.4.0: **Obsidian export**. Any conversation can now be
saved into an Obsidian vault as a Markdown note with one click — frontmatter properties, one
heading per turn, tool calls folded into callouts, charts and data files copied alongside as
attachments. Nothing else in the workbench changed in behaviour; the v1.4.0 notes still describe
everything else.

Three design decisions shape the feature and are recorded in [`docs/OBSIDIAN.md`](../docs/OBSIDIAN.md):

- **Manual.** A note is written only when you click **Save to Obsidian** in the sidebar (or ask the
  model to, via the `obsidian_export` tool). Pinning, new messages, title edits and compacts never
  touch the vault. Saving again replaces the note with the conversation as it stands.
- **One-way.** The note carries no link, id or anything else that opens the app. The vault is a
  destination; Lumispec writes, nothing points back. The only identifier is the `lumispec_id`
  property, kept so a re-save finds its own file and so Dataview can group notes.
- **Nothing is deleted.** Unpinning or deleting a conversation leaves its note in place. A title or
  colour change since the last save *renames* the note (matched on the `-<id8>.md` suffix); the
  exporter never removes a file from the vault.

Obsidian itself is optional: with `OBSIDIAN_VAULT=<path>` in `.env` the exporter writes plain
Markdown into any folder, on a machine with no Obsidian installed.

Two commits on `dev` (2026-10-29), 18 files, +1,200 / −39.

## 📓 Obsidian export

**Turn it on.** Open **Plugins** and switch on **Obsidian Export** (off by default). The card finds
the vaults Obsidian knows about by reading its own registry — native, Flatpak and Snap installs —
and shows the one it will write into: the vault currently open in Obsidian, else the most recently
used, else whatever `OBSIDIAN_VAULT` says. Pick another from the dropdown, set the folder inside the
vault (default `Lumispec`), and choose whether tool results (on) and the model's reasoning (off) go
into the note. With no vault anywhere the card says so in amber and enabling raises a warning
toast; nothing is written until a vault exists.

**Save.** Hover a conversation in the sidebar and click the vault icon that appears next to the
pin. A toast shows the path that was written. The route is `POST /api/conversations/:id/obsidian`;
it answers 400 while the plugin is off and 409 when no vault resolves.

**What a note looks like.** `<Folder>/<session colour>/<slug>-<id8>.md`, so the vault's file
explorer mirrors the sidebar filter and the `lumispec/<colour>` tag makes each session one tag
search:

```yaml
---
title: "Tasks: fetch sites, select top news worthy attention"
lumispec_id: "f49d242b-e702-456e-b9f6-9d0a06ad7367"
created: "2026-10-25T16:39:48.046Z"
updated: "2026-10-25T16:50:52.625Z"
session: "amber"
pinned: true
model: "Qwen3.8-27B"
messages: 2
tokens: 83996
tools_used: ["current_datetime", "run_python", "web_fetch", "web_search"]
tags: ["lumispec", "lumispec/amber"]
---
```

- `## 🧑 <local time>` / `## 🤖 <local time>` per turn; assistant text verbatim (it is already
  Markdown). The auto-submitted session-init prompt is skipped, as in the UI.
- Tool calls → one folded `> [!info]-` callout each, titled with the tool and its query/URL, body
  trimmed to 1,500 chars. `_markdown` results are used as-is (they are tables already); results
  auto-saved to CSV link the file instead of inlining it; tool errors use `> [!warning]-`.
- Reasoning (when enabled) → a folded `> [!note]- Thinking` callout. Flip the toggle and save
  again to add it retroactively.
- Task-pipeline runs → `## 🎯 Pipeline`, `### Step n — …`, `#### Subtask n.m — …`, each with its own
  callouts and output; a failed step shows an open `> [!failure]` callout.
- Applets are cut out into `<slug>-<id8>-applet-<n>.html` sidecars and replaced by
  `> [!example]- Applet (chartjs) — [[file]]`. Obsidian cannot render them inline; the link opens
  the file. Chart.js charts therefore stay unrendered in Obsidian — accepted.
- User-attached images and `/files/<name>` data files referenced in the text are copied into the
  vault's attachment folder (honouring `.obsidian/app.json` → `attachmentFolderPath`, default
  `<Folder>/attachments/`) and the links rewritten to `[[name]]`.
- Footer: `Exported from Lumispec · <updated>`. No URL.

Writes are atomic (`.tmp` + rename, so Obsidian never reads a half-written note), path-guarded to
the vault root, and idempotent: saving an unchanged conversation twice produces a byte-identical
file.

## 🧩 Plugin system — generic card fields

Obsidian needed three kinds of control the Plugins panel did not have, so `configUi()` can now
return `fields: [{ key, label, type: 'select' | 'text' | 'boolean', options?, placeholder?, note?,
disabled? }]`. The panel renders them under the slider; each change POSTs
`/api/plugins/:group/toggle` with `{ config: { [key]: value } }`. The server accepts only keys the
plugin declares in its `defaults` (never `enabled` / `mode` / `engines`) and coerces each to the
declared type, so a text field can never overwrite a boolean. A plugin can also export
`beforeCard()`, awaited before its synchronous `cardStatus()` / `configUi()` so they see fresh
config. `getPluginConfig(group)` returns saved config merged over defaults.

## 🗂️ Conversation store — two fields the exporter needed

- **Session colour** was browser-only state (localStorage). The Save-to-Obsidian request now carries
  it and the store keeps it as `conv.session`, persisted with pinned conversations. Nothing else
  reads it yet.
- **Hidden session-init prompts** were only hidden by the UI at send time; the stored message was
  indistinguishable from a real one. They are now stored with `hidden: true`.
- Tool execution `context` now carries `conversationId` in both tool loops. `CLAUDE.md` documented
  it from the start; the routes never set it. The `obsidian_export` tool is the first consumer.

## ⚙️ Configuration

```bash
# Optional. The card normally finds vaults through Obsidian's registry; set this to force a path —
# a vault on a share, or a machine without Obsidian (the exporter only writes Markdown files).
# OBSIDIAN_VAULT=/home/you/obsidian_vault
```

No other `.env` change. The plugin's own settings live in `data/plugins.json` under `obsidian`.

- `npm test`: 13/13.
- Live against a scratch vault on port 3999: card status and enable warning with and without
  `OBSIDIAN_VAULT`; config field validation (bad types rejected, undeclared keys dropped); export of
  a real pinned pipeline conversation (2,364-line note, one applet sidecar); pinning and renaming a
  conversation wrote **nothing**; one Save wrote `Lumispec/cyan/<slug>-<id8>.md`; a second Save after
  a rename moved the note instead of duplicating it.
- Live in Obsidian: the vault registry on the author's machine lists two vaults across native and
  Flatpak installs; the card resolves the open one.

**Known and accepted:** the `model` property is empty when llama-server is down at save time (it
comes from `/props`). Conversations started before this release still show their session-init
prompt in the note, since the `hidden` flag is set at send time.
