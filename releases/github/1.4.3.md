# LLM Workbench: lumispec.ai, v1.4.3

Local-first AI assistant for llama.cpp (and optionally Claude). One feature on top of v1.4.2: **`web_fetch` can return a page as it reads on screen.** "List my top 70 Gmail subjects" used to cost 19 fetches, because the article extractor keeps every DOM text node and a Gmail inbox row is ~500 characters of hidden tooltips, labels and image links around one visible line. It now costs about three.

> 🔌 **Browser Search needs one reload** on `chrome://extensions` after pulling — the extension is v0.6.5 and the Plugins card says "outdated" until you do. No new dependencies, no `.env` change.

**New in v1.4.3:**

- 👁️ **`web_fetch` `view: "text"`** — `article` (default) is unchanged: Readability for an article, the headline list for a front page. `text` returns the page as laid out on screen, one trimmed line per visual row, hidden elements excluded, table and grid cells joined with ` · `. For web applications — mail, calendars, dashboards, boards — and whenever an article result comes back as repeated fragments and image links. The extension sends Chrome's `innerText`; the HTTP tier approximates from markup and says so.
- 🧭 **Reads what Chrome did not lay out** — in an inactive tab Chrome skips layout for virtualized lists, so `innerText` of a loaded Gmail inbox was 593 chars against 24K in the DOM. When `innerText` covers under 10% of the readable DOM text, a computed-style walker substitutes: hidden subtrees dropped, blocks to lines, each leaf table/grid row on one line capped at 240 chars (nested layout tables such as Hacker News stay multi-line). The same test keeps the settle loop probing while an app is still painting its shell.
- 📊 **Measured** — Gmail 142 chars per message, one line each, 2.9 s; Google News text view 208 lines and 36 headlines versus 17 lines with 3.5K chars of URLs in article view; Wikipedia stays better as an article, as intended.
- 🛡️ **Extension self-reporting** — the injected page functions take every value as an argument and return their own errors as data, after a v0.6.0 build referenced a module constant from inside the page and silently turned every fetch into an HTTP fallback.
- 🖼️ **README** — one screenshot: the whole workbench around a World News Dashboard applet built from eight outlets fetched through Browser Search.
- ✅ **`npm test`: 35 tests.**

**Upgrade:** `git pull` → restart → `chrome://extensions` → reload **Lumispec Browser Search** → the Plugins card turns green with v0.6.5. Ask the model for a web app page and it will pick `view: "text"`; you can also say "fetch it as text".

**Run a model** (separate terminal — see README "Choosing & running your model" for the full flag table):
```bash
./llama.cpp/build/bin/llama-server \
  -hf unsloth/Qwen3.8-27B-GGUF:Q6_K_XL \
  --n-gpu-layers 99 --ctx-size 64000 --flash-attn on \
  --cache-type-k q8_0 --cache-type-v q8_0 \
  --spec-default --spec-type draft-mtp \
  --temp 1.0 --top-p 0.95 --top-k 20 --min-p 0.0 \
  --jinja --port 8080
```
