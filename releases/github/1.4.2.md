# LLM Workbench: lumispec.ai, v1.4.2

Local-first AI assistant for llama.cpp (and optionally Claude). A fix release on top of v1.4.1 about one thing: **what `web_fetch` hands the model**. Pages that Chrome rendered perfectly well were reaching the model as nothing, as a login screen, as summaries with every headline missing, or as a list cut mid-headline. Each defect was diagnosed on a saved copy of the real page, fixed generically, and measured on nine other sites.

> 🔌 **Browser Search needs one reload** on `chrome://extensions` after pulling — the extension is v0.5.0 and the Plugins card says "outdated" until you do. No new dependencies, no `.env` change.

**Fixed in v1.4.2:**

- 🌐 **Index pages render as headline lists** — homepages, section fronts and date archives defeat Readability by design (it prunes link-wrapped headlines as "related links" and returns summaries with every headline missing: NYT 0 of 91, Reuters 0 of 90). Such pages are detected generically and rendered as `- [headline](url) — summary` lines. Article pages and homepages Readability already reads well are untouched. `<template>` blocks (a 100K-char NYT interactive that turned the whole page into 0 chars) are stripped first.
- 🧩 **Browser Search extension v0.5.0** — strips script/style/template/svg before the size cap (Gmail's 1.9M chars of inline CSS used to swallow the cap before the body; 43–100% of the bytes on news sites); reads a page until its visible text stops growing instead of at the first 200 characters (Gmail's header used to be accepted as the inbox); a page Chrome rendered **never falls back to cookie-less HTTP** — which is how a signed-in Gmail became a "you are logged out" sign-in page — and any fallback result that reads like a login page says so; CAPTCHAs that live in an iframe (DataDome on Reuters) are named instead of reported as "11 chars of content".
- 📏 **Max chars per fetched page is a card setting** — default 4000 as before, 1000–50000, on both the Web Search & Fetch and Browser Search cards, with the cost trade-off on the card. Pages the extractor cannot read are saved to `logs/browser-debug/`, and a **Save every fetched page** toggle dumps every fetch for parser work.
- 🎨 **Applets survive a dropped last token** — a 19K dashboard ended in `</applet` (the model sampled end-of-sequence instead of the final `>`) and rendered as unstyled tables; the renderer, the history filter and the Obsidian exporter now accept a closing tag that is missing or cut short at the end of the answer. Streaming renders stay strict.
- 🛠️ **Tool-call parser** — repairs two Qwen3.8 shapes (a key that lost its opening quote, the tool named under `"function"`) that once cost 17 wasted rounds, and caps consecutive unparseable-call retries at 3 before forcing an answer.
- ✅ **`npm test`: 34 tests** (was 13) — parser repairs, extractor, browser fetch guards, applet matching, Obsidian.

**Upgrade:** `git pull` → restart → `chrome://extensions` → reload **Lumispec Browser Search** → the Plugins card turns green with v0.5.0. Optionally raise **Max chars per fetched page** on the card for pipeline work.

**Run a model** (separate terminal — see README "Choosing & running your model" for the full flag table):
```bash
./llama.cpp/build/bin/llama-server \
  -hf unsloth/Qwen3.8-27B-GGUF:Q6_K_XL \
  --n-gpu-layers 99 --ctx-size 64000 --flash-attn on \
  --cache-type-k q8_0 --cache-type-v q8_0 \
  --spec-default --spec-type draft-mtp \
  --temp 1.0 --top-p 0.95 --top-k 20 --min-p 0.0 \
  --jinja --port 8080
```
