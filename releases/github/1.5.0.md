# LLM Workbench: lumispec.ai, v1.5.0

Local-first AI assistant for llama.cpp (and optionally Claude). Two features on top of v1.4.2, both about the browser you already have open: **`web_fetch` can return a page as it reads on screen**, and **the model can read a tab you have open — Tab Fetch.**

> 🔌 **Browser Search needs one reload** on `chrome://extensions` after pulling — the extension is 0.7.0 and the Plugins card says "outdated" until you do. No new dependencies, no `.env` change.

**New in v1.5.0:**

- 👁️ **`web_fetch` `view: "text"`** — `article` (default) is unchanged: Readability for an article, the headline list for a front page. `text` returns the page as laid out on screen, one trimmed line per visual row, hidden elements excluded, grid cells joined with ` · `. For web applications — mail, calendars, dashboards, boards. "List my top 70 Gmail subjects" went from 19 fetches to about 3: a Gmail row is 142 characters in text view versus ~500 as markdown; Google News reads five times denser. When Chrome has not laid the page out (inactive tabs skip layout for virtualized lists), a computed-style walker reads it instead.
- 🗂️ **Tab Fetch** — open and prepare a page yourself (login, two-factor, a passed CAPTCHA, filters, scrolling), then say "look at this" or "look at my Chase tab". With **Let the assistant read my open tabs** on, `browser_tabs` lists your open tabs and `web_fetch { tab }` reads one **in place**: never navigated, clicked, typed in, scrolled or closed. One match reads; if two tabs could be the one you meant (two banks, two Chase tabs), it asks. Each read asks for approval unless you turn that off, and autorun never bypasses it. The hidden-tab fetch stays the default; a fetch of an address you already have open now reads that tab instead of loading it again, and a hidden fetch on a site you have open carries your tabs as a hint (or stops, with **Never open hidden tabs on sites I have open**). Off by default. Design: [`docs/TAB_FETCH.md`](docs/TAB_FETCH.md).
- 🧩 **Plugin prompts can follow live config** — a plugin's `prompt` / `routing` may be functions; Browser Search adds the Tab Fetch guidance only while the toggle is on.
- 🛡️ **Extension self-reporting** — the injected page functions take every value as an argument and return their own errors as data, after an intermediate build silently turned every fetch into an HTTP fallback.
- 🖼️ **README** — one screenshot: the whole workbench around a World News Dashboard applet built from eight outlets fetched through Browser Search.
- ✅ **`npm test`: 50 tests** (34 before) — including Tab Fetch resolution and the bridge with a fake extension.

**Upgrade:** `git pull` → restart → `chrome://extensions` → reload **Lumispec Browser Search** → the Plugins card turns green with v0.7.0. For Tab Fetch, switch on **Let the assistant read my open tabs** on the Browser Search card, open the page you want read, and ask.

**Run a model** (separate terminal — see README "Choosing & running your model" for the full flag table):
```bash
./llama.cpp/build/bin/llama-server \
  -hf unsloth/Qwen3.8-27B-GGUF:Q6_K_XL \
  --n-gpu-layers 99 --ctx-size 64000 --flash-attn on \
  --cache-type-k q8_0 --cache-type-v q8_0 \
  --spec-default --spec-type draft-mtp \
  --temp 1.0 --top-p 0.95 --top-k 20 --min-p 0.0 \
  --jinja --port 8080
```
