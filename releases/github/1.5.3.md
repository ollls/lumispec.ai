# LLM Workbench: lumispec.ai, v1.5.3

Three changes on v1.5.2, all from the 2026-11-04 logs.

- **The research budget is a setting.** "Maximum 3 web_search calls and 3 web_fetch calls per user question" was a fixed sentence in the Web Research prompt, which the model narrates back as its "budget"; nothing in the tool loop enforces it. It is now **Max searches per question** / **Max fetches per question** on both the Web Search & Fetch and Browser Search cards (0–10, default 3 / 3; `0` removes that half of the sentence). At the defaults the system prompt is byte-identical, so the KV prefix is unchanged.
- **A template's own data sources override that budget.** Refreshing the eight-outlet World NEWS template, the model weighed "3 fetches" against "fetch fresh data first" and considered fetching three outlets. The `[template: name]` instruction now says to fetch every source the template names, up to 4 in parallel per round, and to report a failed source instead of filling it from memory.
- **The Claude backend's tool rounds parse and disclose like llama's.** Claude's native `<invoke>`/`<parameter>` syntax is parsed instead of burning a repair round; calls dropped by the 4-per-round cap are named to the model (a round of 11 used to lose 7 unannounced), with identical calls collapsed first; `etrade_account` calls are logged once, not twice. The cap disclosure and the log fix apply on either backend.

`npm test`: 70/70. No `.env` change, no extension change, no reload. **Upgrade:** `git pull` → restart.
