# LLM Workbench v1.6.2

## Overview

Lumispec can now tell you about the llama-server it talks to. A new chip icon in the top bar
opens the **Llama Dashboard**: the model and build that are running, GPU memory and
temperature, how fast answers are generated, GPU errors from the kernel log, and how far the
llama.cpp checkout is behind upstream. The top bar also shows each answer's tokens per second
next to the elapsed timer, and was rearranged to use less space.

Four commits on `dev` since v1.6.1 (2026-11-19), 18 files, +1,303 / −17.

## 🖥 Llama Dashboard

Click the chip icon after the tool icon in the top bar. Nothing has to change in how
llama-server is started, and nothing is pulled, built or restarted from the panel.

- **Server and Model.** Build, idle or generating, how long it has been running, the context
  window against the window the model was trained to, tokens held in the slot, the sampling
  values actually in force, model name, quantization, parameter count and file size.
- **GPU.** A memory bar split into llama-server and everything else, with temperature, power,
  load and driver version.
- **Speed.** Generation tokens per second (median and a line of the last 60 answers), prompt
  reading speed, the share of prompt tokens served from the cache, and how many MTP draft
  tokens were accepted. Measured from every answer llama-server gives the app, since the app
  started; **Reset** starts again.
- **Stability.** GPU errors (NVRM Xid) naming the date, code and process, for the last 90 days.
- **Updates.** How many commits the llama.cpp checkout is behind upstream, the recent commits
  that touch the server, CUDA, speculative decoding or chat handling, and the latest release.
  **Check now** asks GitHub again. This card only reports.
- **Launch command.** The flags llama-server is running with right now, with a Copy button.
- **Alerts.** A banner in the panel and an amber dot on the icon when the server is not
  answering, a GPU error occurred in the last 48 hours, GPU memory is over 97% full or the GPU
  reaches 85 °C.

### What it reads, and from where

| Card | Source | Needs |
|---|---|---|
| Server, Model | llama-server `/props`, `/v1/models`, `/slots` | nothing |
| Launch command, uptime, RAM | the `llama-server` process in `/proc` | server on the same machine (Linux) |
| GPU | `nvidia-smi` | same machine |
| Stability | `journalctl -t kernel` | same machine, journal readable |
| Speed | the `timings` of each completion | nothing |
| Updates | the git checkout the binary was built in, GitHub API | internet; a GitHub `origin` |

- **Server on another machine.** GPU, Stability, process and launch command are left out, and
  each card says why: this machine's `nvidia-smi` and journal would describe the wrong
  computer. Updates appears only when `LLAMA_CPP_DIR` names a checkout.
- **A tool that is missing** (`nvidia-smi`, `journalctl`, `git`, `ps`) empties its card with a
  reason; the rest keeps working.
- **`--metrics` is optional.** With it, the Speed card adds totals since llama-server started
  and draft acceptance by position.
- **The update check compares commits, not tags.** llama.cpp releases moved from `b<n>` tags
  to `v1.0.0` on 2026-11-13, so a build number can no longer be compared with a release.
  It makes four unauthenticated GitHub requests, cached for six hours.

### Xid events and `journalctl -k`

`journalctl -k` shows the current boot only. On the development machine it listed none of the
GPU channel hangs on record (Xid 8 on 2026-11-09 and 2026-11-16). The dashboard and the docs
now use `journalctl -t kernel`.

## ⏱ Top bar

- **Tokens per second next to the timer.** After each answer the top bar shows its generation
  speed (`104 tok/s`); the tooltip gives tokens generated, prompt tokens read against tokens
  from cache, and draft tokens accepted. It covers the last round of a chat answer and the
  last step of a task pipeline.
- **Timer and speed are always shown.** `0s` and `0 tok/s` on a new conversation, `… tok/s`
  while an answer runs. Each conversation shows its own last answer until the page is
  reloaded.
- **Tool icon always shown**, starting at 0, so the menus no longer shift when the first tool
  runs.
- **Layout.** Menus start right after the status indicators; the Context bar is 40% shorter;
  the Context bar, timer, speed and Slots are aligned to the right edge.

## 📝 Also

- **README: macros in saved prompts.** A table of `{$date}`, `{$time}`, `{$day}`, `{$month}`,
  `{$year}` and `{$location}`, custom variables and typed pickers, and when they are filled in.
  The saved "Market Tape Analysis" prompt used `{DATE} {TIME}`, which are not macros; it now
  uses the real ones.
- **Route log.** With `ROUTE_LOG=1` each round's `ctx` also carries `speed`.

## ✅ Validation

`npm test`: 184/184 (172 at v1.6.1 + 12 in `test/llamaDashboard.test.js`, covering the parsers
and summaries).

Checked by hand on 2026-11-21 on Linux with an RTX 5090, llama.cpp builds 11719 and 12621: every
card against the live server, the Speed card and the top-bar figure with real answers, and the
panel in Chrome with no console errors. Other machines were simulated, not run: a canned
llama-server on a non-local loopback address for the remote case, an empty `PATH` for missing
tools, a dead address and a malformed `LLAMA_URL`. macOS and Windows were not run; there the
process, GPU and Stability cards report no reading. The `… tok/s` state during a long answer and
the top-bar figure after a task pipeline were not seen on screen.

The system prompt is unchanged from v1.6.1.

One optional `.env` setting, `LLAMA_CPP_DIR` (the llama.cpp checkout, when it cannot be found
from the running binary). No extension change.
**Upgrade:** `git pull` → restart → hard-reload the page.
