# LLM Workbench v1.5.3

## Overview

Three changes on v1.5.2, all from the 2026-11-04 logs: **the "3 searches, 3 fetches per question"
budget the model keeps quoting is now a setting**, **a template that names its own data sources is
exempt from that budget**, and **the Claude backend's tool rounds parse and disclose like llama's**
(native `<invoke>` syntax read, calls dropped by the per-round cap named to the model, E\*TRADE
calls logged once).

Four commits on `dev` since v1.5.2 (2026-11-04 and 2026-11-06), 16 files, +460 / −55.

## 🎚 The research budget is a card setting

"I have a budget of 3 web_fetch calls" is one sentence in the Web Research prompt section —
`Maximum 3 web_search calls and 3 web_fetch calls per user question` — fixed since the monolithic
`tools.js`. The model reads it and narrates it back. **Nothing in the tool loop enforces it**: the
loop's own limits are 20 rounds, 4 parallel calls, 3 identical repeats and the context wind-down.

It is now two number fields, on both the **Web Search & Fetch** and **Browser Search** cards:

| Field | Config key | Default | Range |
|---|---|---|---|
| Max searches per question | `web.maxSearchesPerQuestion` | 3 | 0–10 |
| Max fetches per question | `web.maxFetchesPerQuestion` | 3 | 0–10 |

- A `0` drops that half of the sentence; both at `0` drop the line, and the model is told no budget.
- One stored value under `web`, shown on both cards like the fetch cap. The cost it bounds is
  context spend (count × "Max chars per fetched page" ÷ 4 tokens), the same on either transport;
  only one of the two prompts is live at a time; and the HTTP fallback crosses plugins mid-call.
- At the defaults both system prompts are byte-identical to v1.5.2, so llama-server's KV prefix
  is unchanged. Changing a value rebuilds the prompt and costs one full re-prefill.
- A card edit reaches the next prompt build: both `prompt()` builders are now functions reading
  `cachedResearchLimits()`, refreshed by `beforeCard`, each search/fetch call and each build.
- In a pipeline every step is its own "question", so a subtask-per-source fan-out never hit the
  budget in the first place.

`researchLimitLine()` builds the sentence (singular/plural, the 0 cases), `clampResearchLimits()`
is the pure clamp, `researchLimitFields()` returns the two descriptors.

## 📄 A template's own sources override the budget

Refreshing the eight-outlet **World NEWS** template on 2026-11-04, the model read the budget
("Maximum 3 web_fetch calls per user question") against the template instruction ("fetch fresh
data first") and deliberated between fetching three outlets and substituting searches for front
pages. The two instructions conflicted and the numeric one won.

The `[template: name]` instruction block gains one sentence:

> When the template names its data sources (sites, feeds, tickers, files), fetch EVERY one of
> them — the per-question web_search/web_fetch budget does not apply to a template's own sources.
> Fetch up to 4 in parallel per round. If a source fails, say so in the output instead of filling
> it from memory.

The verbatim-copy rules are unchanged. The expansion moved out of the chat route into
`src/services/templateExpansion.js` — pure, with the template lookup and the logger injected —
so the text the model receives is testable.

## 🤖 Claude backend: tool rounds parse and disclose like llama's

Three failures from one session with `LLM_BACKEND` switched to Claude:

| What happened | Now |
|---|---|
| The model wrote its native `<invoke name="…"><parameter name="…">` syntax for `run_python`, followed by an empty `<tool_call>` block. The parser found nothing and the loop burned a repair round. | `parseInvokeBlocks()` reads that form like a `<tool_call>` block: each value coerced to the type the tool declares (number, boolean, object/array), code indentation kept. Blank `<tool_call></tool_call>` blocks are skipped. The repair message names `<invoke>` when that is what it sees. |
| A round of 11 tool calls lost 7 to the 4-per-round cap without a word to the model. | `capToolCalls()` collapses identical calls first (same name + arguments), keeps the first 4, and `droppedCallsNote()` lists every dropped call in that round's results message: `⚠ N tool call(s) were NOT executed — at most 4 run per round: … Call them again in your next round if you still need them.` Both loops (chat and pipeline). |
| Every `etrade_account` call landed in `logs/` twice, a millisecond apart: its own raw-vs-formatted entry plus the executor's generic one. | A tool can declare `logsItself: true`; the executor then skips its generic entry. |

`getSystemPrompt()` adds a "do not use `<invoke>`, `<parameter>`, `<function_calls>`" rule **only
while `config.llm.backend === 'claude'`**, so the llama prompt and its KV prefix stay
byte-identical. The cap disclosure and the single E\*TRADE log entry apply on either backend.
