# LLM Workbench v1.3.0

## Overview

A reliability release for long tool runs on a local model. Since v1.2.1 the tool loop has learned to
see the context wall coming, the prompt prefix has been made byte-stable so llama-server's KV cache
survives from turn to turn, and a new **Retain** toggle lets the model keep its own reasoning in
context. Around that core: the web fetch path was re-tiered and its browser bounded, pipeline output
folds instead of stacking, routing decisions can be logged for analysis, and two search/grep bugs
that returned confident empty results are fixed.

Fourteen commits on `master` since `v1.2.1` (2026-08-14 → 2026-10-18), 26 files, +1,688 / −904.

## 🧮 Context budget — the tool loop is bounded by tokens, not just rounds

`MAX_TOOL_ROUNDS` capped how many rounds a turn could take; nothing capped how large the prompt got.
Every round appends its tool results, so a long run walked into the slot's context wall — where
llama-server does **not** error. It returns HTTP 200 with `finish_reason: "length"` and an empty
message, which surfaced as a blank assistant bubble with the whole turn discarded.

Both tool loops (chat and task pipeline) now measure the real prompt at the top of every round and
wind down at 80% of the live slot's `n_ctx` (`src/routes/conversations.js:322`):

- `countPromptTokens()` asks llama-server's `/tokenize` — accurate to ~0.1%, ~78 ms for a 64K prompt,
  with a `chars / 3.5` fallback (`src/services/llm.js:55`). Deliberately **not** `timings.prompt_n`:
  that counts tokens *processed*, so with KV-cache reuse it reads 37 for a 64K prompt and would never
  see the wall coming.
- `trimOldToolResults()` shrinks the oldest tool results to 400 chars, keeping the newest 3 intact
  (`src/services/llm.js:97`).
- The wind-down round is **terminal**: a `{tool_status}` event announces it, an "answer now, no
  tools" instruction is injected, and any tool calls in that round are logged and ignored — there is
  no room to feed results back in.

**Empty and truncated answers are never silent any more:**

- `finish_reason: "length"` with content → a "⚠ Answer cut off at the context limit" marker is appended.
- An empty final answer in chat is stored as an explicit error with its `toolUses` and `reasoning`
  intact, so the work stays on screen.
- An empty step in the pipeline is a **halt**, not a pass-through: a step's output is the next step's
  only context, so handing one an empty string would make every downstream step invent from nothing.
- llama-server dying mid-stream (GPU fault, restart) no longer overwrites the message with a bare
  error string — the accumulators live outside the `try`, so the catch stores the same shape as the
  success path and every gathered tool result survives.

The limit comes from the live slot, so raising `--ctx-size` raises the budget with no code change.
`LLAMA_MAX_CONTEXT` is only the fallback when `/slots` is unreachable, and `MAX_PREV_RESULT_CHARS`
(the pipeline's step-to-step channel) is now configurable — unlike the token budget it does not scale
with `n_ctx`.

## ⚡ Stable prompt prefix — the KV cache survives across turns

The system prompt embedded the current date and time to the second. It is the first message of every
request, and llama-server reuses a slot's KV cache only up to the first differing token, so every turn
diverged at message one and re-prefilled the entire conversation: ~6,400 processed prompt tokens on
every turn of a short chat.

The clock now rides on the user message. `getDatetimeStamp(date)` renders a single `[Now: ...]` line
(`src/tools/index.js:662`) that is appended to the newest user message at send time and never stored.
Every stored message carries `sentAt` (`src/services/conversations.js:90`), and the history rebuild
re-derives each earlier user message's stamp from it, so prior turns are byte-identical across
requests. The system prompt only names the timezone and tells the model where to find the stamp.

Measured after the change: 6,393 processed prompt tokens on a cold slot, then **~80 per turn** — only
the new question. Messages without `sentAt` (older pinned conversations) are sent as stored.

## 🧠 Retain toggle — send the model's reasoning back as context

Think shows the model's reasoning; **Retain** keeps it. With the new slider next to Think
(`src/views/index.html:342`), every assistant message handed to llama-server carries
`reasoning_content`, which the Qwen3 chat template renders as that message's `<think>` block. The
model sees its own prior thinking in later tool rounds and later turns. Default **off** — retained
reasoning makes every prompt larger.

- **Tool rounds** attach *that round's own* reasoning via the `asAssistant()` helper
  (`src/routes/conversations.js:194`, `src/routes/taskProcessor.js:317`), so the prompt prefix matches
  what the model generated and the KV cache can reuse it.
- **History** attaches the stored turn trace to each assistant message. Tool rounds are not replayed
  in history, so the whole turn's thinking rides on the final answer.
- **Pipeline** steps stay isolated: `prev.result` between steps is content only.
- **Context budget**: `countPromptTokens()` counts `reasoning_content`, so the 80% wind-down still
  measures the true prompt.
- **Claude backend**: `reasoning_content` is stripped before the request; the Anthropic API rejects
  unknown fields.
- The flag is read at send time: toggling off drops all prior reasoning from the next prompt.

No server flag is needed — the Qwen3.8 template preserves reasoning for every assistant message when
`preserve_thinking` is undefined. Design note with the verification steps and measurements:
[`docs/RETAIN.md`](../docs/RETAIN.md).

## 🌐 Web research — bounded browser, tiered fetch, DuckDuckGo and Keiro unbroken

An audit of 569 logged `web_fetch` and 444 `web_search` calls drove a set of fixes in
`src/tools/plugin-web.js`:

- **`puppeteer-core` 24 → 25** (`package.json:27`). v25 removed `browser.isConnected()`; the cache
  guard called it through optional chaining, so the first browser fetch worked and every later one
  threw. Replaced with the version-agnostic `connected` getter.
- **One Chrome, not four.** `getBrowser()` cached the resolved browser, not the in-flight launch, so
  four parallel fetches launched four instances and orphaned three. The promise is now cached
  (`src/tools/plugin-web.js:53`), a disconnect drops the instance, and the browser closes after 5 min
  idle instead of living for the process lifetime.
- **Hard timeouts.** `page.content()` inherited puppeteer's 180 s default; six fetches stalled ~200 s
  each. `protocolTimeout: 30000` caps it. `networkidle2` → `domcontentloaded` plus a capped settle,
  with images/media/fonts aborted — byte-identical extraction, 31% faster on an ad-heavy page.
- **New `auto` fetch mode, now the default** (`src/tools/plugin-web.js:102`). Regular and stealth
  are not separate tiers — measured, they are the same speed and byte-identical on 4 of 5 targets.
  The real boundary is HTTP-only vs runs-JavaScript, so the ladder is stealth → browser, escalating
  on a throw, a challenge-page match, or implausibly short text (`looksBlocked`,
  `src/tools/plugin-web.js:237`). The cheap result is kept when the expensive one comes back smaller.
  Wikipedia / The Verge / react.dev now serve from stealth in 210–485 ms where browser mode cost
  1–3.4 s and launched Chrome.
- **DuckDuckGo was being dropped** whenever fetch mode was `regular`, on the false premise that it
  needs stealth; the UI mirrored this by persisting an empty engine list, so search stayed dead after
  switching back. 13 of 444 logged searches died this way. Removed in all three places. DDG also
  retries once without quotes on an empty result (`src/tools/plugin-web.js:179`), and the prompt tells
  the model to skip quoted phrases.
- **Keiro results were silently discarded.** The parser read `data.data.search_results`; Keiro
  returns a top-level `results` array. With Keiro + DuckDuckGo enabled, every search merged only
  DuckDuckGo's hits and the sources label never showed Keiro. Both shapes are now accepted
  (`src/tools/plugin-web.js:133`).

## 🎯 Task pipeline — folded output, chronological streaming

- **Completed steps fold.** A pipeline step emits a full formatted answer; a 13-subtask run stacked
  thirteen article-length outputs into one bubble. Completed steps now collapse into a `<details>`
  one click away, the last step stays open (it is the answer), and the live step is capped at
  `max-h-60` with its own scrollbar. Applied to both the live path and `renderStepBlocks`
  (`src/public/js/app.js:1163`), which rebuilds the view after a run.
- **Subtasks stream top-to-bottom.** `subtask_start` spliced each new subtask *above* the previous
  one, so a 3-subtask run rendered live as `h1 h2 h3 out3 out2 out1`. Appending fixes it; both
  complete handlers now skip a step whose content is already final so a fold is never destroyed.

## 🔍 Route decision logging and a narrower fabrication guard

- **`ROUTE_LOG=1`** writes one JSONL record per tool-loop routing decision to
  `logs/routes_YYYY-MM-DD.jsonl` (`evalPredicates`, `src/services/routeLog.js:39`). Pure
  observation, off by default. Two analysis scripts ship in `scripts/`: `analyze-logs.mjs`
  (classifies executed tool calls by payload shape) and `analyze-prompt.mjs` (measures how much of
  each request is tool-protocol scaffolding).
- **Fabrication guard narrowed.** `looksLikeChainQuote()` (`src/services/chainQuote.js:36`) now
  requires an actual chain row — two or more quote fields on a line — instead of the old loose
  Greeks regex, and the guard also requires that no tool ran this turn. Answers grounded in
  transactions, positions, or a `run_python` pass over a saved chain CSV no longer trip it.
- **Repair predicates made disjoint.** All 9 records labelled `bare-json` in the first 411-record
  corpus contained a `<tool_call>` tag — they were wrapped calls with broken JSON, and the model was
  told "your call was not wrapped" 9 times out of 9. `bare-json` now means no tag anywhere,
  `malformed-tag` means tag present but unparseable, and each repair message describes the defect it
  fires on. Drift records with an unacted predicate keep full content
  (`UNACTED_PREDICATES`, `src/services/routeLog.js:87`).

## 🛠️ Source tools — `source_read` grep is path-aware, bounded, and skips `node_modules`

Two confident-looking empty results, fixed in `src/tools/plugin-source.js`:

- Any glob containing `/` returned `matchCount: 0`, because GNU grep's `--include` only matches the
  basename. Globs are now matched in JS against the root-relative path, with `**`, `?` and `{a,b}`
  support. A glob that matches no files returns a warning explaining both forms, so zero can't be
  mistaken for "this code doesn't exist".
- A repo-wide grep failed with `ENOBUFS`: no `node_modules` exclusion and a 512 KB buffer. The
  candidate list now comes from the same `find` the tree action uses (`TREE_FIND_CMD`,
  `src/tools/plugin-source.js:10`), files are passed as argv (no shell interpolation of `$` or
  backticks), 4 MB per 500-file chunk, and an overflow returns a partial `N+` result instead of
  failing.

## ⚙️ Configuration

Three optional variables, all documented in `.env.example`:

| Variable | Default | Purpose |
|---|---|---|
| `LLAMA_MAX_CONTEXT` | 131072 | Fallback context limit, used only when `/slots` is unreachable. Keep at or below `--ctx-size` or the wind-down never fires. |
| `MAX_PREV_RESULT_CHARS` | 32000 | Chars of the previous step's output a pipeline step receives. Does not scale with `n_ctx`. |
| `ROUTE_LOG` | unset | `1` enables JSONL route-decision logging. |

**Dependency change:** `puppeteer-core` `^24.40.0` → `^25.8.0`. Run `npm install` after upgrading.
`puppeteer-extra` and the stealth plugin stay at their last published versions (frozen since 2023).

## ✅ Validation

- Context budget: verified by feeding one slot a 56,001-token prompt untruncated while 4 slots were
  live; `--ctx-size` confirmed as the per-slot window. `/tokenize` accuracy ~0.1% vs. the server's own
  count.
- Stable prefix and Retain: `timings.prompt_n` measured per turn — 6,393 cold, then 81 / 80 with
  Retain on; 779 on the turn the toggle flips off, 1,097 when it flips back on.
- Web fetch: timings and byte-equality measured against the live sites named above; the `auto`
  heuristic replayed against the 560-fetch log would have caught all 59 thin-or-blocked results.
- Grep: the four originally failing calls now return 50 / 6 / 37 / 21 matches; the `ENOBUFS` pattern
  returns 45; a 16,551-line match truncates cleanly.
- Keiro: live probe returned HTTP 200 with 10 parsed hits where the old parser returned 0.
- Pipeline rendering: handler sequence replayed against a minimal DOM shim for 1 and 3 subtasks,
  flat tasks, and the confirm-command insert.

**Known and unfixed:** identical URLs requested twice in one parallel round are fetched twice; tool
rows and reasoning blocks are pooled at task level mid-run rather than attributed per subtask. Both
predate this release.
