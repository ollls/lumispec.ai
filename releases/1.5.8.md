# LLM Workbench v1.5.8

## Overview

The model can now troubleshoot its own applets. It could never see them: in later turns an
applet reaches the model as `[Applet: html visualization]`, tool rounds are not replayed, and
whatever goes wrong inside an applet happens in the browser. Asked to fix a blank chart, it
rewrote one from memory of the request. A **Troubleshoot** button now hands it the browser's
view of the applet and the way to read back the code it wrote.

Three commits on `dev` since v1.5.7 (2026-11-10), 10 files, +406 / −14.

---

## 🛠 Troubleshoot an applet

- **Troubleshoot button** next to "Save as Template" under every applet. It fills the prompt and
  sends nothing: what you had typed becomes the "Problem:" line, and an empty line gets a selected
  `<describe what is wrong>` placeholder.
- **Browser report.** Every applet reports uncaught errors, unhandled promise rejections,
  `console.error`, failed resource loads and non-OK `fetch` responses to the page (20 per applet).
  The prompt carries them together with the rendered height, the visible text and the canvas count,
  headed "facts, not necessarily defects".
- **`conversation_read` tool** (always on). Returns the exact source of an applet from an earlier
  answer in the same conversation; also a turn's stored tool results (`what: "tools"`) or its
  reasoning (`what: "reasoning"`). The prompt includes the exact call, and a routing hint tells the
  model to read before fixing anything you report as broken.
- **Guard rails in the prompt.** It explains how applets are hosted (the frame grows to its content
  and the chat scrolls), and tells the model to fix only the described problem and to ask when none
  is described.

Measured on an applet stuck on "Loading…": the report carried `fetch: 404 /files/…`, the model
called `conversation_read` (627 chars back) and answered with a corrected applet.

## ✂ An applet is never clipped

The first Troubleshoot run on a working dashboard, sent with no problem described, had the model
take "6338px tall" for the defect and rebuild the page as a fixed 620px box with an inner scroll
region. The host forces applet pages to grow to their content with no scrolling of their own, so
the frame showed the first 620px of 6,338 with no scrollbar. The host now sizes the frame to the
larger of what the applet asks for and what it renders.

## ✅ Validation

`npm test`: 127/127 (119 at v1.5.7 + 8, `test/conversationRead.test.js`). Exercised in Chrome
against a local model: the Troubleshoot prompt on a failing applet, the model's `conversation_read`
call and corrected answer, and the previously clipped dashboard rendering at full height. Only the
failed-fetch diagnostic was exercised; the other error kinds were not. Whether the model asks
instead of guessing when no problem is described was not re-run.

The system prompt gains one tool and one routing line, so each conversation's next turn re-reads
the prompt once. No `.env` change, no extension change.
**Upgrade:** `git pull` → restart → hard-reload the page.
