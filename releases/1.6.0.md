# LLM Workbench v1.6.0

## Overview

Lumispec can now read a book with you. Point the new **Books** plugin at a folder of Markdown or
text files, a single file, or a PDF: it indexes the book in the background, you make it the
**open book**, and the assistant answers from it first and names the section each answer rests
on. The release also carries **Troubleshoot on any answer**, which has been on `dev` since
v1.5.8: the model reads back what its tools actually returned and corrects an earlier answer
instead of rerunning the prompt.

Eight commits on `dev` since v1.5.8 (2026-11-10), 25 files, +2,705 / −84.

## 📚 Books — index a book, open it, chat against it

New plugin, **off by default**. User guide: [`docs/BOOKS.md`](../docs/BOOKS.md).

- **What a book is.** A folder of `.md` / `.markdown` / `.txt` files anywhere on disk, one such
  file, or a PDF with a text layer. Your folder or file is never modified; the index lives in
  `data/books/<id>/`.
- **Add it from the card or from chat.** Type a path into **Add a book** on the Books card, or
  ask: *"add ~/books/sicp as a book called SICP"*. The book is registered, opened, and indexing
  starts.
- **The open book comes first.** One book is open at a time. While it is open the assistant
  searches it before any other tool, reads the best sections, names the section an answer rests
  on (`ch03.md#2`), and says so first when the book does not cover the question.
- **Book only.** A checkbox on the card: while a book is open, web search, Python and every
  other plugin's tools are withheld, and the assistant answers "not in this book" instead of
  looking elsewhere.
- **Questions work before indexing finishes.** Search ranks sections over the full text plus
  the summaries written so far, so it needs no index. It is keyword-based (no embeddings).
- **Long files are read piecewise.** A file over 16,000 characters is cut into sections at
  paragraph breaks, and at headings where possible, so a whole novel in one `.txt` works.
- **Indexing is a background job on the server,** one LLM call per section. It is started by
  adding a book, the card's **Index N sections** button, or by asking; it stops by itself after
  three failures in a row and resumes where it stopped. Editing a file marks only its sections
  for re-indexing.
- **Two tools:** `book_library` (list, open, close, add, index, status, stop, remove — add and
  remove ask for approval) and `book_read` (search, read, contents — the open book only).

### PDF books — two steps, both reported

- **Step 1, convert.** `scripts/pdf_to_md.py` (PyMuPDF) turns the PDF into Markdown: headings
  from the PDF's own outline, running headers and page numbers dropped, monospaced blocks fenced
  as code, line-end hyphenation rejoined. The Markdown is kept under `data/books/<id>/source/`;
  nothing is written next to the PDF.
- **Step 2, index.** The usual background indexing. The book opens as soon as step 1 is done.
- **The card says which step is running** ("Step 1 of 2 — converting X.pdf to markdown: page
  120/690…"), with a toast on each change of step. A failed conversion stays on the card with
  its reason: a scanned PDF has no text layer and needs OCR first; a missing PyMuPDF shows the
  install command for your Python environment.
- **Measured** on *Math for Programmers*: 690 pages converted in 1.4 s, 445 headings, 761 code
  blocks, 121 sections of which 118 start at a heading.

### For plugin authors

Two additions to the plugin interface, both optional:

- **`exclusive()`** — while it returns true, only that plugin's tools plus `core` are listed in
  the system prompt and executable. Books' "Book only" is the first user.
- **`configChanged(current, changed)`** — called on a card field save before the entry is
  written; may return a `notice` or `warning` for the toast. Books uses it for "Add a book".

The frontmatter helpers moved to `src/services/frontmatter.js`, shared by Books and the wiki.

## 🩺 Troubleshoot on any answer

*Revise an answer against its own evidence instead of rerunning it.* User guide:
[`docs/TROUBLESHOOT.md`](../docs/TROUBLESHOOT.md).

- **A red Troubleshoot on every answer,** at the bottom right of the bubble. It appears on
  hover and stays visible on an answer that failed, was stopped or was cut off.
- **It fills the prompt and sends nothing.** The prompt names the answer, carries your problem
  line, quotes the text you selected in the bubble, and includes the exact `conversation_read`
  call that returns what the tools actually produced. The correction is a new answer; the
  stored one is never edited.
- **A turn report comes with it,** headed "facts, not necessarily defects": tool counts, which
  results failed, fell back, hit a sign-in page or were truncated, long results with their
  index, pipeline task errors and clipped hand-offs.
- **Works on good runs too:** "verify these numbers", "you missed two sources".
- **`conversation_read` reads one result in full.** `{"what":"tools","tool":n}` returns a single
  stored tool result up to 20,000 characters; the list view numbers every entry.
- **Your own wording.** A saved prompt titled **Troubleshoot** replaces the guidance paragraph.

### Fixes from the first test session

- **The model answered with the history placeholder.** Asked for a fourth applet, it wrote the
  literal line `[Applet: html visualization]` and described a chart it had not drawn. The
  placeholder now says what it is and that it must never be written, and an answer that carries
  it with no real applet gets one retry in the same turn.
- **A guessed message number no longer costs a round.** Asked without the button, the model
  tried a user message, then an answer without an applet. `conversation_read` now returns the
  nearest answer that has the requested part and says so.
- **`conversation_read` is not evidence.** A correction turn whose only call was
  `conversation_read` used to be reported as a tool run to read back. An answer that holds an
  applet now gets the applet call first.

## ✅ Validation

`npm test`: 153/153 (127 at v1.5.8 + 26: `test/books.test.js` 14, `test/troubleshoot.test.js`
10, two more in `test/applets.test.js`). The Books tests run on temporary directories with a
fake summarizer and a fake converter.

In the development library: one PDF book (*Math for Programmers*, 690 pages, 121 sections
indexed) and one folder book (84 sections indexed), both built with a local Qwen3.8-27B.
Book only, the scanned-PDF and missing-PyMuPDF messages, and a single file as a book were not
re-run by hand for these notes; they are covered by the unit tests.

With Books off, the system prompt differs from v1.5.8 only by the Troubleshoot changes (the
`conversation_read` description and the applet history placeholder), so each conversation's
next turn re-reads the prompt once. Turning Books on, opening or closing a book, changes the
prompt again from the Books section on.

No `.env` change, no extension change. PDF books need PyMuPDF in the Python environment
(`PYTHON_VENV`); the card shows the install command when it is missing.
**Upgrade:** `git pull` → restart → hard-reload the page.
