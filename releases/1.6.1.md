# LLM Workbench v1.6.1

## Overview

Lumispec can now keep facts across conversations. Ask it to remember something and, after your
approval, the new **Memories** plugin carries that fact into every later chat. The release also
documents the llama-server **slot layouts** measured on the RTX 5090 (one slot with a 112K
window is now the recommended one), records every silent tool-call repair in the route log, and
states plainly that applets are not isolated from the app.

Ten commits on `dev` since v1.6.0 (2026-11-13), 41 files, +1,994 / −92.

## 🧠 Memories — facts kept across conversations

New plugin, **off by default**. User guide: [`docs/MEMORY.md`](../docs/MEMORY.md).

- **Save by asking.** "Remember that I prefer metric units." The assistant shows the exact text
  and waits for your approval. Saving under the same name replaces the old text, and the prompt
  shows what it replaces.
- **Approval is never skipped.** Save and forget always ask, and Autorun does not bypass the
  prompt: a fetched page that says "remember this" would otherwise plant a line in every later
  conversation.
- **No search step.** While the plugin is on, every memory has one line at the end of the
  assistant's instructions, on every request and in every task-pipeline step. A memory of up to
  200 characters is carried in full; a longer one as its description, and the assistant reads
  the full text when it is relevant.
- **List size.** The list holds 8,000 characters by default (card field, 2,000 to 40,000). When
  it is full the oldest memories stay, the card status turns amber, and the ones left out are
  marked "not listed".
- **Colors, only on request.** "Remember this for this kind of chat" ties a memory to the
  session color. With **Only memories matching the chat color** on, a tagged memory appears
  only in chats of its color; untagged ones appear everywhere.
- **The card lists every memory:** color swatch, name, text and date, with color chips and a
  search box. Hover a row and click ✕, then "Delete?", to forget one without going through chat.
- **Plain files.** One Markdown file per memory in `data/memory/` (not in git); edit, add or
  delete them by hand.
- **One tool:** `memory` (list, read, save, forget). It stays available under Books' "Book
  only".
- With the Claude backend the memories are sent to Anthropic with each request; the card says
  so.

### For plugin authors

Three additions to the plugin interface, all optional:

- **`promptTail({ session })`** — a section rendered at the very end of the system prompt, for
  content that changes over time, so the KV prefix before it survives.
- **`alwaysOffered`** — the plugin's tools stay listed and executable while another group is
  exclusive, like `core`.
- **`listDelete(id)`** plus a `list` element in `configUi()` — a card list with color chips,
  search and a two-click delete (`POST /api/plugins/:group/list/delete`).

The frontend now sends the chat's session color with every message and pipeline run, and the
server passes it to the system prompt and the tool context.

## ⚡ Slot layouts for llama-server

Documentation only; the app reads the window from the live slot and needs no change. See
"Choosing a slot layout for llama-server" in the [README](../README.md).

- **One slot, 112K window is the recommended layout on a 32 GB card**
  (`--ctx-size 114688 --parallel 1`). The launch scripts in the README use it.
- **The default four slots share one pool** of `--ctx-size` tokens; they never had that many
  each. Each slot costs about 600 MiB whatever the window.
- **Four slots with a window each** (`--parallel 4 --no-kv-unified`) is presented for cards
  with 48 GB or more, with a sizing rule and a variant that fits 32 GB.
- **Measured cache reuse when conversations alternate:** one slot re-processed 4 of 3,701
  prompt tokens on each return; the default four-slot pool with the slot named in the request,
  as this app does, re-processed all 3,701. [`docs/RETAIN.md`](../docs/RETAIN.md) and
  `.env.example` carry the same note.

## 🔍 Route log records every tool-call patch

Needs `ROUTE_LOG=1`. Observation only: what is parsed and executed is unchanged.

- The parser repairs malformed tool calls silently, so counting re-prompts alone undercounted
  model errors. Each round's record now carries `fixes` (one entry per patch: normalized keys,
  Python literals, repaired newlines, bare JSON, `<invoke>` syntax, and the `run_python`
  auto-fixes), `ctx` (measured prompt, limit, completion, finish reason) and `backend`.
- `node scripts/output-fixes.mjs [name-filter]` tabulates patched and re-prompted rounds by
  window fill, per backend. It exists to answer whether errors climb as the window fills.
