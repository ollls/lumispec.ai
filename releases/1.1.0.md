# LLM Workbench v1.1.0

## Overview

A knowledge-hardening release. The headline feature is **Cite mode** — a per-conversation discipline that guards against *documentation hallucination*, the failure mode where LLM-authored docs contain confident, fluent claims about architecture that does not exist in the code. It also ships a hotel-search reliability fix and refreshed model-launch documentation.

This is a purely additive release: `dev` was 3 commits ahead of `master` with no diverging changes on `master`. Every code path below was read in full and exercised at runtime before release.

## 🎯 Cite Mode — Code-Citation Discipline

A new per-conversation **Cite** toggle (cyan accent `#06b6d4`, in the input-area button column, **on by default**). When active, it enforces that architectural claims are backed by `(file:line)` citations across three coordinated layers.

The design principle is a deliberate **refuse-vs-warn asymmetry**:

- **Deterministic checks** (does a citation resolve on disk?) → **hard refusal**
- **Heuristic checks** (does this sentence *look* like an uncited claim?) → **soft warning**

This means fabrications that slip past the fuzzy pattern matcher can still be caught by the exact broken-citation backstop at index time.

### Layer 1 — System-prompt rule

When Cite mode is on, `getSystemPrompt({ cite })` injects `CITE_RULES` into the system prompt:

- Every architectural claim in a markdown doc write (`"X provides Y"`, `"X is implemented as Z"`, file paths, function names, defaults, behaviors) must carry a `(src/path/file.js:LINE)` citation.
- **Read before drafting** — use `source_read` to find the real code first; if a claim can't be cited, write `TODO: needs verification` instead of writing it.
- The same rule applies to architectural claims in chat answers.
- **No training-data inference** — the only source of truth is files read with `source_read` in the conversation.

### Layer 2 — Diff-preview claim highlighter (soft — never blocks)

When `source_write` or `source_edit` writes a `.md`/`.markdown` file under Cite mode, two mechanical checks (no LLM, no network) run on the result:

- **Pattern-based** (`extractAddedLines` + `detectUncitedClaims`) — parses the unified diff and flags claim-shaped *added* lines that lack a nearby citation. Three narrow, conservative patterns: project-relative file path followed by a behavioral verb; backtick-quoted identifier followed by an implementation verb; numeric value with a unit. Patterns are intentionally low-false-positive to avoid training users to ignore the highlighter.
- **Reference-based** (`validateCitations`) — resolves every `(file:line)` / `` `file:line` `` citation in the new content against `SOURCE_DIR`.

Combined warnings attach to the tool result as `_citeWarnings`, render in an **amber block above the diff preview** (so the human approver sees them before the change), and are **stripped from LLM context** — they are purely a UI affordance. **The write is never blocked**; the human decides.

### Layer 3 — `wiki_index` strict mode (hard — refuses)

When `wiki_index` runs under Cite mode:

- A stricter summarization prompt (`CITE_INDEX_RULES`) is appended: numbers must appear in the source verbatim (no paraphrase/rounding), no training-data inference or cross-project analogy, vague source ⇒ vague summary, no invented key topics, stub-not-pad for empty docs.
- Sampling temperature drops from **0.2 → 0.1** for tighter, less inventive output.
- `validateCitations` runs on the produced entry. **Any broken citation refuses the wiki-entry write entirely** and returns the offending list — this is the hard backstop that would have automatically caught the original fabrication incident.
- Successful entries are stamped `cite_mode: true` in frontmatter as provenance.

### Wiring & shared helpers

- Three deterministic helpers — `extractAddedLines`, `detectUncitedClaims`, `validateCitations` — live in `src/tools/index.js` as exports, consumed by both `plugin-source.js` (diff highlighter) and `plugin-wiki.js` (path validator). `validateCitations` includes a path-escape guard (citations resolving outside `SOURCE_DIR` are refused).
- `cite` is read from the request body in both `POST /:id/messages` and `POST /:id/tasks`, passed to `getSystemPrompt`, and threaded into **every** tool-execution context object — main loop, over-limit path, forced-answer last-chance, safety-net, and the task pipeline's `buildToolContext`.
- `_citeWarnings` is stripped from the LLM-facing result string in both the chat route and the task processor.
- Frontend: `state.citeEnabled` persisted to `localStorage` (`'citeEnabled'`, default true); warning snippets are HTML-escaped before rendering.

## 🐛 Fixes

### Hotel search silently returning empty results

LiteAPI's `/data/hotels` endpoint returns an empty result set — with no error — when `hotelName` or `cityName` is supplied without a `countryCode`. The `hotel` tool description and the travel system prompt now make `countryCode` an explicit requirement for name/city searches (e.g. `"US"`, `"IT"`, `"TH"`), so the LLM stops issuing searches that quietly return nothing. Prompt-guidance change; no execution-logic change.
