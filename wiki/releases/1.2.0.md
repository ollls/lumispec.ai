# LLM Workbench v1.2.0

This document details the v1.2.0 release of LLM Workbench, a frontend-only update introducing a sidebar color filter for conversations. The feature adds a tab-like chip strip above the conversation list that filters chats by session color, modeled on note-taking app patterns. The release is purely additive, touching only `src/public/js/app.js` and `src/views/index.html` without altering server, route, or data-model components. It includes specific behaviors for tab semantics, self-hiding logic, count badges, and keyboard accessibility, along with persistence via `localStorage` and automatic fallbacks for empty states.

## Key topics
- Sidebar Color Filter — A horizontal strip of chips that filters the conversation list by session color, with one active chip at a time.
- Tab Semantics & Interaction — Clicking an active color chip clears the filter to `All`; chips include count badges and active-state visual cues like a 2px bottom border.
- Persistence & Edge Cases — Filter choice persists in `localStorage` under `sidebarFilter`; automatically resets to `All` if the selected color has zero conversations.
- Accessibility — The filter strip uses `role="tablist"` and `role="tab"` with roving `tabindex` and arrow-key navigation for keyboard support.
- Wiring & State — New state variables `state.sidebarFilter` and `state.sessionTitles` manage the filter and tooltips; `renderSidebar` computes counts and renders the filtered list.
- Validation — Code passes `node --check` and server boots successfully, though visual verification in a browser was not performed at release time due to lack of initial colored conversations.
