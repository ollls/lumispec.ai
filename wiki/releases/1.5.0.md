# LLM Workbench v1.5.0 Release Notes

This release introduces two primary features focused on browser interaction: a new `text` view for `web_fetch` that returns pages as they appear on screen (one line per visual row) to improve density for web applications like Gmail, and "Tab Fetch," which allows the model to read currently open browser tabs without navigating or modifying them. The `text` view utilizes `document.body.innerText` when available, falling back to a DOM walker for inactive tabs where layout is skipped, using a 10% threshold to determine readability. Tab Fetch is controlled by four new boolean settings in `data/plugins.json` under the `browser` key, including `readTabs` (off by default) and `confirmTabReads` (on by default). The browser extension was updated to version 0.7.0, requiring a manual reload in Chrome to enable the new capabilities, and the plugin system now supports function-based prompts and routing. Validation included 50 tests and live scenarios with six open tabs, confirming that the text view reduces fetch costs for Gmail from 19 to approximately 3.

## Key topics
- `web_fetch` text view — Returns one trimmed line per visual row, excluding hidden elements, to optimize reading of web apps like Gmail and dashboards.
- Tab Fetch — Allows the model to read open tabs in place without navigation, with deterministic resolution logic that asks for clarification if multiple tabs match.
- Extension 0.7.0 — Adds `tabs` and `read` capabilities, requires a Chrome reload, and includes new popup buttons for listing tabs and reading the current tab.
- DOM Walker Fallback — Activates when `innerText` covers under 10% of readable text, walking the DOM to drop hidden subtrees and join table rows capped at 240 characters.
- Configuration Booleans — Four new settings in `data/plugins.json`: `readTabs`, `confirmTabReads`, `reuseOpenTab`, and `protectOpenSites`.
- Plugin System Updates — Supports function-based `prompt` and `routing` fields to allow dynamic guidance based on live configuration.
