# LLM Workbench v1.5.6

This release introduces three guards to prevent single tool results from exceeding the model's context window, specifically addressing issues where large outputs like a 7,000-file repository tree (428K chars) caused 400 errors against a 64K slot. The `tree` command now summarizes results over 300 files, and a new executor ceiling caps every serialized tool result at 50,000 chars. Additionally, a wind-down mechanism trims tool results to 4,000, 1,500, or 400 chars if the prompt remains over 90% of the slot capacity. The changes involve 10 files with +259 / −14 lines of code, implemented in `services/toolResultLimits.js` and tested via `test/toolResultLimits.test.js`.

## Key topics
- Tool result limits — Three guards prevent tool outputs from sinking a turn by summarizing, capping, and trimming.
- Tree summarization — `tree` outputs over 300 files are summarized with top-level layout and first 300 paths; `source_read` gains an optional `path` parameter.
- Executor ceiling — Serialized tool results are capped at 50,000 chars (~12K tokens) with a small envelope for overflow.
- Wind-down fitting — If the prompt exceeds 90% of the slot, tool results are iteratively cut to 4,000, 1,500, then 400 chars using llama's tokenizer.
- Validation — `npm test` passes 112/112 tests; upgrade requires `git pull` and restart.
