# LLM Workbench v1.0.0 Release Notes

This document details the features and architecture of LLM Workbench v1.0.0, a production-ready AI assistant featuring a dual LLM backend (llama.cpp and Claude API) and a modular plugin system. It defines eight core source code tools for self-modifying codebases, a web research system with three search engines (Tavily, Keiro, DuckDuckGo) and three fetch modes (Regular, Stealth, Browser), and a two-stage task execution system comprising the TaskMaster prompt decomposer and the Task Pipeline executor. The release includes integrations for E*TRADE brokerage data, LiteAPI travel booking, and a hierarchical RAG wiki plugin that supports a self-improving knowledge loop.

## Key topics
- Source Tools Family — Eight tools (`source_project` through `source_git`) for reading, editing, executing, and versioning code with safety tiers and diff previews.
- Web Research System — Configuration for Tavily, Keiro, and DuckDuckGo engines with Regular, Stealth, and Browser fetch modes; multi-engine results are deduplicated and sliced to the first 8 entries.
- TaskMaster + Task Pipeline — TaskMaster decomposes prompts into bullet lists via `POST /api/conversations/:id/decompose`, while the Task Pipeline executes them with chained top-level context (capped at 32000 chars) and isolated sibling subtasks.
- E*TRADE Integration — Full brokerage access including account management, options trading Greeks, real-time quotes for up to 25 symbols, and export to CSV/JSON/Markdown.
- Dual LLM Backend — Supports local inference via llama.cpp for privacy and cloud API via Claude for complex reasoning, with configurable fallback routing.
- Wiki Plugin & Knowledge Loop — Hierarchical RAG system using `wiki_scan` and `wiki_index` to compress source markdown into a wiki index, supporting a self-improving feedback loop for documentation synchronization.
- Plugin Architecture — Modular tool system with dependency graph validation, hot reload capabilities, and always-on `core` and `execution` groups.
- Precision Mode — Computation discipline rules requiring vectorized Pandas, limiting scripts to 40 lines, and mandating diagnostic scripts before retrying errors.
