# LLM Workbench v1.4.0 Release Notes

This release introduces Browser Search, an optional Chrome extension that allows the LLM to perform web searches and fetches through the user's real, logged-in browser instance, bypassing bot detection and headless browser limitations. The feature integrates via a WebSocket bridge and falls back to existing HTTP methods (Tavily, Puppeteer, etc.) if the extension is unavailable or fails. The plugin system was extended to support plugin supersession, live status lines, and enable warnings, while the context bar was corrected to report actual measured context tokens rather than cumulative work metrics.

## Key topics
- Browser Search Plugin — Registers `web_search` and `web_fetch` tools served via a Chrome extension using a hidden tab, supporting DuckDuckGo, Brave, Bing, and Google engines.
- Chrome Extension — Manifest V3 extension (`extension/`) that loads URLs in inactive tabs, returns rendered HTML, and maintains a WebSocket connection to the server.
- Plugin Supersession — New `supersedes` capability allows one plugin to hot-unload and replace another, graying out the replaced plugin's UI while preserving its configuration.
- Context Bar Correction — Replaces `timings.total_tokens` with `context_tokens` (measured prompt + completion) to accurately reflect the current slot usage in chat and task pipelines.
- Bot Wall Handling — Implements retry logic for CAPTCHA/challenge pages (waiting 0.8s, 3s, 4s) and caches failed URLs for 90s to prevent immediate re-fetch loops.
- Configuration Variables — Introduces `BROWSER_SEARCH_TOKEN`, `BROWSER_SEARCH_TIMEOUT_MS` (default 25000), and `BROWSER_SEARCH_BROWSER` for controlling extension authentication, timeouts, and launch behavior.
