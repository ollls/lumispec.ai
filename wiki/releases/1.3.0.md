# LLM Workbench v1.3.0 Release Notes

This release focuses on reliability for long tool runs on local models, introducing a token-based context budget that winds down at 80% of the live slot's `n_ctx` to prevent silent failures. It implements a byte-stable prompt prefix by moving the datetime stamp to the user message, allowing llama-server's KV cache to survive across turns, reducing processed prompt tokens from ~6,400 to ~80 per turn. A new **Retain** toggle allows the model to keep its own reasoning in context via `reasoning_content`, while the web fetch path is re-tiered with a bounded browser and a new `auto` mode. Additional improvements include folded pipeline output, chronological streaming, route decision logging, and fixes to `source_read` grep and search engine parsers.

## Key topics
- Context budget — Measures real prompt tokens via `/tokenize` and trims old tool results to avoid context walls.
- Stable prompt prefix — Moves datetime to user messages to ensure byte-identical prefixes for KV cache reuse.
- Retain toggle — Sends `reasoning_content` back to the model to preserve prior thinking in context.
- Web research — Bounded browser usage, `auto` fetch mode, and fixes for DuckDuckGo and Keiro search parsers.
- Task pipeline — Completed steps fold into `<details>` tags, and subtasks stream top-to-bottom.
- Route decision logging — `ROUTE_LOG=1` writes JSONL records for tool-loop routing decisions.
- Source tools — `source_read` grep is now path-aware, bounded, and skips `node_modules`.
- Configuration — New variables `LLAMA_MAX_CONTEXT`, `MAX_PREV_RESULT_CHARS`, and `ROUTE_LOG`.
