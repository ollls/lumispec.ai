# LLM Workbench v1.5.8

This release introduces a Troubleshoot feature that allows the model to debug its own applets by providing browser-side error reports and access to previous code via a new `conversation_read` tool. It addresses previous limitations where applets were invisible to the model in later turns and errors occurred in the browser context. The update includes three commits on `dev` since v1.5.7, affecting 10 files with +406 / −14 lines. It also fixes an issue where applets were clipped by forcing the host frame to size to the larger of the requested or rendered height.

## Key topics
- Troubleshoot button — Fills the prompt with user input as "Problem:" and includes browser error reports.
- Browser report — Captures uncaught errors, promise rejections, console errors, failed loads, and non-OK fetch responses (20 per applet).
- conversation_read tool — Always-on tool that retrieves exact applet source, tool results, or reasoning from earlier turns in the same conversation.
- Applet clipping fix — Host now sizes the frame to the larger of what the applet asks for and what it renders, preventing fixed-height clipping.
- Prompt library update — Removes the System Monitoring Dashboard prompt added in v1.5.7.
- Validation — 127/127 tests passing (119 at v1.5.7 + 8 new in `test/conversationRead.test.js`); exercised in Chrome against a local model.
